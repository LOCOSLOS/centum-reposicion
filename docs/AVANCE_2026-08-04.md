## Piloto de forecasting

### Motor local

Se agregó un prototipo Python sin dependencias externas en `forecasting/` con:

- agregación semanal por artículo y sucursal;
- consolidación de sociedades;
- tratamiento separado de demanda regular e intermitente;
- promedio reciente ponderado y componente estacional auditable;
- exclusión de semanas censuradas por quiebre cuando esa información exista;
- backtesting temporal;
- métricas MAE, WAPE y sesgo;
- lectura y escritura CSV;
- evaluación directa de la salida JSON de n8n;
- horizonte semanal y horizonte acumulado de cuatro semanas.

La configuración calibrada sobre datos reales utiliza:

- 13 semanas recientes;
- decaimiento `0,82`;
- peso estacional `0,10`;
- media reciente para demanda intermitente.

Se probaron 36 combinaciones y se descartó TSB como configuración predeterminada porque empeoró el resultado sobre esta muestra. El motor conserva esa alternativa únicamente para experimentación controlada.

### Workflow del dataset piloto

- ID: `PZb95UdRFHdMybZ6`.
- Nombre: `Forecasting - Dataset piloto semanal (MANUAL)`.
- Estado: manual, inactivo y de solo lectura.
- No escribe en Supabase.
- Selecciona hasta 50 series regulares y 50 intermitentes.
- Consulta hasta 27 meses disponibles, pero solo exige 52 semanas para no devolver una muestra vacía.

La ejecución `2018` terminó correctamente con los tres nodos y produjo:

- 4.849 filas semanales;
- 100 series artículo-sucursal;
- 50 regulares y 50 intermitentes;
- cobertura de muestra desde el 1 de julio de 2024 hasta el 27 de julio de 2026.

La diferencia entre 52 y 78 semanas no es material. Se conserva 52 semanas como opción provisional porque presenta menor error absoluto y menor subestimación. Todavía no alcanza calidad suficiente para automatizar envíos sin revisión humana.

En las ventanas acumuladas el modelo proyectó menos unidades que las observadas. Antes de ajustar artificialmente el resultado se deben incorporar reglas de cobertura, stock de seguridad y quiebres históricos disponibles.

## Arquitectura acordada

```text
n8n
  extracción y orquestación
        ↓
Supabase / Postgres
  ventas, stock, tránsito y resultados
        ↓
Python
  pronóstico y cálculo de reposición
        ↓
Interfaz web
  revisión, explicación y exportación
```

- n8n no ejecutará por sí solo todo el cálculo estadístico.
- Python se desarrolla y valida localmente; la infraestructura definitiva de ejecución se decidirá después.
- No se contrató ni desplegó Cloud Run u otro servicio nuevo.
- Vercel continúa como opción para la futura interfaz, no como motor de cálculo intensivo.
